# Хороший полицейский — бот для мессенджера MAX

Самостоятельный бот: сам собирает новости из официальных источников МВД,
сам отбирает истории о добрых поступках сотрудников, сам отправляет их
кураторам на модерацию и сам публикует одобренное в канал MAX.

Это **отдельный проект** от Telegram-версии (`kindpolicebot`): свой
токен, своя база, свой сервер. Боты не связаны и не мешают друг другу.

---

## Быстрый старт

```bash
pip install -r requirements.txt
```

```bash
cp .env.example .env
```

Заполните `.env` (как минимум `MAX_BOT_TOKEN`, `MAX_MODERATOR_CHAT_ID`,
`MAX_PUBLISH_CHAT_ID`, `MAX_ADMIN_IDS`, `AI_PROVIDER_API_KEY`), затем:

```bash
python main.py
```

Проверки без сети:

```bash
python -m tests.test_pipeline && python -m tests.test_max_flow
```

## Порядок подключения

1. **Токен.** Получите у `@MasterBot` в MAX (`/create`), положите в
   `MAX_BOT_TOKEN`.
2. **Запустите бота** и напишите ему `/whoami` — он ответит вашим
   идентификатором в MAX. Впишите его в `MAX_ADMIN_IDS` и перезапустите.
   Идентификаторы MAX не совпадают с телеграмными.
3. **Чат модераторов.** Создайте закрытый чат, добавьте туда бота и
   кураторов, отправьте `/chatid`. Полученное число — в
   `MAX_MODERATOR_CHAT_ID`.

   Если бот ещё не запущен, id можно узнать и без него:

   ```bash
   python -m tools.show_chats
   ```

   Скрипт читает события с сервера MAX и печатает id всех чатов, где
   побывал бот, плюс идентификаторы людей для `MAX_ADMIN_IDS`.
   Запускайте его только при остановленном боте: событие достаётся
   тому, кто прочитал первым.
4. **Канал публикации.** Добавьте бота администратором в канал и
   отправьте туда `/chatid`. При добавлении бот сам напишет id чата.
   Число — в `MAX_PUBLISH_CHAT_ID`.
5. **Проверьте:** `/diag` покажет, что настроено, а `/test_publish` —
   отправит в канал тестовый пост.
6. **Меню команд** задаётся вручную у `@MasterBot` (`/commands`) —
   через API это сделать нельзя. Список для копирования есть в шапке
   `max_bot.py`.

## Чем версия для MAX отличается от Telegram

Возможности Bot API MAX уже, поэтому часть интерфейса устроена иначе.
Всё перечисленное проверено на живом токене — документация местами
отстаёт от действительности.

| Что | Telegram | MAX |
|---|---|---|
| Постоянная клавиатура снизу | есть | **нет** — меню открывается сообщением с кнопками по `/menu` и кнопкой «⬅️ Меню» |
| Авторизация | `/bot<токен>/метод` | заголовок `Authorization: <токен>`, **без** `Bearer` |
| Адрес API | api.telegram.org | `botapi.max.ru` (указанный в части документации `platform-api2.max.ru` не отвечает) |
| Получатель | в теле запроса | в query: `/messages?chat_id=…` или `?user_id=…` |
| Кнопки | `reply_markup` | вложение `inline_keyboard` в `attachments` |
| Список чатов бота | доступен | `GET /chats` боту **недоступен** (404) — `chat_id` узнаём из событий |
| Меню команд | `setMyCommands` | только вручную у `@MasterBot`: `PATCH /me` отвечает 404 |
| Добавление в группы | разрешено | **запрещено по умолчанию** — включается на dev.max.ru: ⋮ → Настройки → Приватность (только после модерации бота) |
| История событий | `getUpdates` с offset | окно по маркеру: слишком старый маркер возвращает пусто |
| Лимит текста | 4096 | 4000 |
| Библиотека | aiogram | своя обёртка `maxapi.py` — аналога aiogram для MAX нет |

Логика отбора новостей, рерайта, рисования карточек, ИИ-помощника и
справочника — та же, что в Telegram-версии.

## Источники новостей

| Источник | Сколько | Зачем |
|---|---|---|
| **Ленты МВД по регионам** (`NN.мвд.рф/news/rss`) | 81 лента, ~1620 новостей за обход | Главный источник: первоисточник с уже известным регионом |
| **Федеральная лента МВД** (`мвд.рф/news/rss`) | 20 | Общероссийские новости ведомства |
| **Telegram-каналы ведомств** (`t.me/s/…`) | 10 каналов | Истории, уже отобранные пресс-службами |
| **Ленты СМИ** (РИА, ТАСС, РГ, Интерфакс, Лента, Коммерсантъ и др.) | 11 лент | Резонансные случаи; шумные, поэтому фильтруются по ключевым словам |

Каналы MAX как источник подключить нельзя: страница канала отдаёт
только описание, посты подгружаются скриптами и в HTML их нет. MAX
остаётся каналом **публикации**, а не сбора.

### Почему новости ранжируются

Полутора тысячам новостей за обход не нужна проверка моделью: почти
всё это сводки о наркопритонах и мошенниках. `pipeline/ranking.py`
оценивает каждую новость по словам (спас, вынес из огня, реанимация —
в плюс; изъято, приговор, поздравил — в минус) и выстраивает очередь:
модель смотрит лучших кандидатов первыми и останавливается по лимиту
`MAX_LLM_CHECKS` (по умолчанию 80).

Ничего не выбрасывается навсегда — низкий балл означает лишь конец
очереди. На живом прогоне три поста нашлись за **6 обращений к модели**.

### Фото, видео и текст со страницы новости

Ленты МВД отдают в RSS **только заголовок** — ни текста, ни картинок.
Поэтому для отобранных кандидатов бот догружает страницу новости
(`pipeline/media_extract.py`) и берёт оттуда:

* **полный текст** (обычно 1000–1600 символов вместо пустого поля) —
  без него модель судила о новости по одной строке заголовка, а рерайт
  пересказывал заголовок заголовком;
* **снимки в оригинальном размере**: на странице они лежат уменьшенными
  копиями вида `IMG_1234-800x600.jpg`, а оригинал доступен по тому же
  адресу без суффикса — 1280×960 и больше вместо 800×600. Гербы,
  эмблемы и иконки отсеиваются по именам файлов, иначе в пост уходил бы
  герб вместо фотографии с места события;
* **видео**, если оно есть.

Видео берётся и из публичных Telegram-каналов ведомств: у поста с
роликом в разметке есть прямая ссылка на mp4. Ролик скачивается
(не больше 45 МБ) и уходит в пост вместо фотографии — запись спасения
показывает событие целиком, тогда как кадр из неё лишь момент. Если
видео не удалось получить, пост выходит с фотографией или карточкой.

Страница запрашивается только для кандидатов, прошедших ранжирование,
а не для всех полутора тысяч новостей.

## Иллюстрации: генерация по смыслу новости

Картинка к посту берётся по порядку, сверху вниз:

1. **Фото или видео из официального источника.** Приоритет всегда за
   настоящей съёмкой с места события.
2. **Сгенерированная иллюстрация** — если своих снимков нет.
3. **Фирменная карточка** — если генератор недоступен. Рисуется
   локально через Pillow, без сети и ключей, поэтому картинка есть у
   каждого поста.

### Почему текст новости не отдаётся генератору напрямую

Новости МВД написаны канцелярским языком про процессуальные действия.
На запрос «сотрудники ОМВД в рамках профилактического мероприятия
оказали содействие» генератор нарисует что угодно. Поэтому кадр сначала
сочиняет языковая модель (`pipeline/image_prompt.py`): она читает
новость и описывает **сцену** — место, время суток, погоду, что
происходит в этот момент. И только это описание уходит в генератор.

Если иллюстрировать нечего (отчёт, статистика, поздравление), модель
возвращает `NONE`, и пост получает карточку. Это проверено на живых
новостях: спасение ребёнка из горящего дома превращается в описание
деревенской улицы серым осенним днём, а сводка по статистике ДТП —
в `NONE`.

### Границы, которые нельзя нарушать

Тема ведомственная, поэтому в промпте жёстко запрещены:

* **узнаваемые лица** — люди только со спины, издалека или не в фокусе:
  выдавать нарисованных людей за участников события нельзя;
* **форма, шевроны, гербы, номера машин** — официальная символика не
  должна подделываться, форма описывается просто как `dark uniform`;
* **любой текст в кадре** — генераторы пишут бессмыслицу;
* **кровь, травмы, тела, оружие в действии** — канал про добрые дела.

На каждую сгенерированную картинку бот ставит надпись
**«Иллюстрация · сгенерировано ИИ»** (правый нижний угол,
`AI_IMAGE_LABEL`). Это не косметика: без надписи нарисованный кадр
читается как фотография с места происшествия. Убирать её не следует.

### Настройка

Генерация картинок живёт **отдельно от текстового провайдера**: у
`api.baza-ai.org` эндпоинта `/images/generations` нет вовсе (проверено,
отвечает 404), а из 41 модели ни одна не рисует. Поэтому:

| Переменная | Назначение |
|---|---|
| `IMAGE_API_BASE` | адрес сервиса картинок |
| `IMAGE_API_KEY` | ключ для него; если пусто — берётся `AI_PROVIDER_API_KEY` |
| `AI_PROVIDER_IMAGE_MODELS` | список моделей, перебираются по порядку |
| `AI_PROVIDER_IMAGE_QUALITY` | `low` / `medium` / `high` |
| `AI_IMAGE_LABEL` | надпись на картинке |

Модели перебираются по списку: первая ответившая и рисует. Линейка
`gpt-image-1` выключена поставщиком 23.10.2026, поэтому в списке по
умолчанию идут `gpt-image-2.5-*` и `gpt-image-2.6-*`, а `dall-e-3` —
последним запасным вариантом. Ответ `404`/`405` на самом эндпоинте
распознаётся как постоянный отказ, и генерация отключается на весь
запуск, чтобы не ходить к сервису впустую на каждой новости.

Параметр `response_format` намеренно **не** отправляется: линейка
`gpt-image` всегда отдаёт base64 и отклоняет этот параметр с ошибкой.

### Что проверено вживую

10.11.2026 цепочка прогнана целиком через **ProxyAPI**
(`https://api.proxyapi.ru/openai/v1`, оплата в рублях, работает с
сервера в РФ без VPN): новость о спасении пожилой женщины из горящего
дома → описание кадра от языковой модели → картинка 1024×1024 от
`gpt-image-2.5-flare` с пометкой об ИИ. Доступны 11 моделей линейки
`gpt-image`.

Этот прогон вскрыл три дефекта, которых не было видно на моках:

| Что сломалось | Как исправлено |
|---|---|
| Пометка всегда пересохраняла файл как JPEG, даже если он `.png` — расширение расходилось с содержимым, а и Telegram, и MAX определяют тип по имени файла | формат берётся по расширению |
| Линейка `gpt-5` отвечает `400 Unsupported parameter: 'max_tokens'` | клиент повторяет запрос с `max_completion_tokens` и запоминает отказ на весь запуск |
| Рассуждающие модели тратят весь лимит токенов на рассуждения и возвращают пустой текст при `finish_reason: length` | один повтор с увеличенным лимитом |

## Служебная часть

Служебные команды видны **только** пользователям с ролью в базе:
обычному пользователю бот отвечает отказом. Карточки на модерацию
уходят в закрытый чат `MAX_MODERATOR_CHAT_ID`, где обычных
пользователей нет.

### Модератор
`/fetch` · `/pending` · `/stats` · `/audience` · `/schedule_status` · `/chatid`

### Администратор
`/diag` · `/schedule_on` · `/schedule_off` · `/set_interval N` ·
`/list_moderators` · `/add_moderator` · `/remove_moderator` ·
`/clear` → `/clear_confirm` · `/cleanup_images` · `/assistant_log` ·
`/broadcast текст` · `/add_resource` · `/list_resources` ·
`/remove_resource` · `/reseed` · `/test_publish`

### Как назначить модератора

В MAX человек не видит собственный числовой идентификатор и не может
продиктовать его администратору, поэтому роли выдаются кнопками:

1. В чате модерации отправьте `/add_moderator` — бот покажет участников
   чата кнопками (себя и других ботов он не предлагает).
2. Нажмите на нужного человека. Имя сохраняется вместе с ролью, поэтому
   в списке видно людей, а не цифры.
3. `/list_moderators` показывает всех, у кого есть доступ, и кнопки
   «Снять» рядом с модераторами.

Запасной путь из личной переписки: `/add_moderator 3959125`. Свой
идентификатор человек узнаёт командой `/whoami`.

Администратора, заданного в `MAX_ADMIN_IDS`, снять через бота нельзя —
только правкой переменной окружения. Снять роль с самого себя тоже
нельзя: иначе единственный администратор мог бы случайно закрыть себе
доступ к боту.

На карточке новости три кнопки: «✅ Опубликовать», «❌ Отклонить»,
«🖼 Другая картинка». Нажатие от постороннего игнорируется, а повторное
нажатие не публикует пост второй раз — статус меняется одним
атомарным запросом к базе.

## Деплой

В проекте есть `Dockerfile`: на хостинге включите «Использовать
собственный Dockerfile». Он ставит шрифт DejaVu — без него Pillow
нарисует на карточках пустые квадраты вместо кириллицы.

Точка входа — `main.py`. Нужен Python 3.10+.

Шрифт для карточек лежит в репозитории: `assets/fonts/DejaVuSans.ttf`
и `DejaVuSans-Bold.ttf` (DejaVu 2.37, свободная лицензия, файл
`LICENSE.txt` рядом). Это сделано намеренно: в образе `python:slim`
системных шрифтов нет, и Pillow рисует вместо русских букв пустые
квадраты. Установка пакета шрифтов в `Dockerfile` спасает только
когда сборка идёт через него, а автосборка хостинга его игнорирует —
файл в репозитории работает при любом способе сборки.


**Не запускайте два экземпляра с одним токеном**: оба будут забирать
события длинным опросом, и часть сообщений потеряется.

**База** лежит в `storage/bot.db`. Если хостинг пересоздаёт контейнер
при деплое, база обнулится: пропадут роли, история и пользователи.
Администраторы и справочник восстановятся сами, остальное — нет.
Для постоянного хранения смонтируйте диск и укажите путь в `DB_PATH`.

## Структура

```
main.py                  точка входа
max_bot.py               бот: меню, разделы, модерация, админка
maxapi.py                клиент Bot API MAX (своя обёртка)
app.py                   веб-панель модерации (необязательна)
config.py                настройки из .env
content/                 памятки, телефоны, справочник источников
pipeline/                отбор, рерайт, генерация картинок, ИИ-помощник
sources/                 RSS и публичные Telegram-каналы как источники
storage/                 модели и SQLite
tools/
  show_chats.py          узнать chat_id без запуска бота
tests/
  test_pipeline.py       логика без сети (141 проверка)
  test_max_flow.py       сценарии бота через события MAX (100 проверок)
```

Telegram-каналы остаются **источниками новостей** и в этой версии:
бот читает их публичные страницы, токен Telegram для этого не нужен.
